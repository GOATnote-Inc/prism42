# H1 — MedAgentBench extension

## Dispatch summary

Port the existing two-rail Prism harness to agentic clinical workflows by adding
MedAgentBench as a new corpus under the clinical rail. The work includes
standing up the Stanford ML Group FHIR environment locally, wiring the harness's
executor branch to the FHIR side-effect verifier, and running a baseline +
harness comparison that survives a 3-trial reproducibility check. Ships as an
extended clinical corpus plus a delta report; does not replace the HealthBench
Hard primary metric.

## Notes for the dispatcher

- External dependencies: Docker + `jyxsu6/medagentbench` image on port 8080 running on the executor host. The dispatcher must confirm the environment is reachable before the live-call sub-task is authorized.
- The FHIR environment contains de-identified profiles only; no PHI handling required, but redaction-scan discipline from `docs/clinical-handling.md` §4 still applies to any packet material derived from runs.
- Reproducibility gate: N ≥ 3 baseline runs, reported as mean ± 95% CI half-width; harness-delta adopts the paired-design rule from `CLAUDE.md` §4 (paired mean Δ 95% CI excludes 0). The old `±0.02` absolute gate was retired 2026-04-22 as statistically unachievable (`docs/seed-stability-2026-04-22.md`). If the FHIR side-effect verifier itself is non-deterministic, HALT and escalate — do not publish a delta.
- Scope guard: this task adds a clinical-rail corpus, not a new rail. R3 FHIR tool adapter is the implementation vehicle.
