# H5 — Model-behavior disclosure workflow automation

## Dispatch summary

Automate the packet-preparation half of the clinical-finding disclosure
workflow described in `docs/clinical-handling.md`. Given a `confirmed_delta`
case, the script produces a reviewable disclosure packet (redacted
conversation, rubric excerpt, delta evidence, physician-attestation stub)
for the Anthropic feedback channel. The script itself does not send anything;
the human-of-record sends, per the physician-review gate. Ships as a
gated script plus a two-packet dry-run log.

## Definition of done

- `scripts/disclose_clinical_finding.py` passes `scripts/check_sdk_containment.py` (no live-send code path — the script's job is packet preparation only).
- Two dry-run packets land under `findings/private/` with all fields populated from `docs/clinical-handling.md` §3 schema.
- `scripts/redaction_scan.py` exits non-zero if the packet contains any of the regex-matched PII patterns (names, institutions, MRN-like IDs).
- Tests cover: (a) every required packet field is present, (b) physician-attestation stub is present and unfilled, (c) finding out of scope per §1 is rejected.
- `make verify-disclose-dry-run` exit 0.
- `make verify-all` still exit 0.

## Notes for the dispatcher

- Physician sign-off (`docs/clinical-handling.md` §5, Brandon Dent, MD) is a HARD gate on any real disclosure. This task only automates packet preparation; the send-to-Anthropic step remains human.
- Two dry-run packets must be reviewed and approved (per roadmap §7 H5 gate) before the first real submission. This approval step is out of scope for the agent — the agent's job is to make the two packets reviewable.
- Redaction-scan is deliberately conservative (regex), not LLM-based. Missed PII false-negatives are acceptable at this layer because the physician-review gate is a second, stricter pass.
- `findings/private/` stays gitignored per `docs/clinical-handling.md` §7; the template and the dry-run-log metadata are the only committed artifacts.
